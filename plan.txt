          HOSTEL MANAGEMENT SYSTEM - MASTER EXECUTION PLAN (plan.txt)

Project Type: College Mini Project / Project-Based Learning (PBL)

Methodology: Educational Bottom-Up Approach with 4-Member Parallel Execution
Architectural Stack: React.js (Vite) + Node.js + Express.js + MongoDB (Mongoose)

Deployment: Vercel (Frontend), Render (Backend), MongoDB Atlas (Database)

--------------------------------------------------------------------------------
1. PROJECT PHILOSOPHY & WORKFLOW STRATEGY
--------------------------------------------------------------------------------
This project follows a step-by-step, educational project-based learning model.
While executed in a single environment, the work is divided across 4 distinct 
member roles operating in parallel, starting from basic scratch:

1. PALAK (Docs & Planning Lead): 
   - Starts FIRST by creating structured markdown documentation in `docs/`.
   - Owns operational modules (Attendance, Leave, Visitors), Postman QA, and final docs.

2. ANUSHKA (Auth UI & Admin Operations Developer): 
   - Starts by creating basic Login & Register interface code.
   - Owns Admin/Warden operational views, student tables, room management, and complaint resolution UI.

3. BHOOMI (Frontend Lead & Student Portal): 
   - Starts by building basic website layout (Navbar, Sidebar) and Admin Dashboard UI skeleton.
   - Owns the complete Student Portal UI (Dashboard, Room Application, Fee view, Complaints, Notices).

4. AYUSH (Lead Architect & Backend Developer): 
   - Starts backend from scratch: folder structure setup, selecting dependencies, basic Express server.
   - Owns MongoDB models, REST APIs, JWT/RBAC security, business logic, integrations, and deployment.

PHASE 2: DATABASE SCHEMAS & BACKEND INFRASTRUCTURE (AYUSH WORK)
================================================================================
[ ] Step 2.1: MongoDB Connection Setup (`server/config/db.js`).

[ ] Step 2.2: Define 13 Mongoose Schemas (`server/models/`)
    - `User.js` (name, email, password, role, avatar, isActive)
    - `Student.js` (rollNumber, department, year, phone, guardian, roomAllocation)
    - `Hostel.js` (name, code, totalFloors, totalRooms, capacity, gender, warden)
    - `Room.js` (hostel, roomNumber, floor, capacity, occupied, feeAmount, status)
    - `Allocation.js` (student, hostel, room, startDate, status)
    - `Fee.js` (student, term, amount, dueDate, status)
    - `Payment.js` (fee, student, transactionId, paymentMethod, status)
    - `Complaint.js` (student, category, subject, description, priority, status)
    - `Notice.js` (title, content, targetAudience, category, publishedBy)
    - `Attendance.js` (student, date, status, markedBy)
    - `Leave.js` (student, startDate, endDate, reason, status, reviewedBy)
    - `Visitor.js` (student, visitorName, relation, phone, entryTime, exitTime, status)
    - `Notification.js` (recipient, title, message, link, isRead)

[ ] Step 2.3: JWT Auth & RBAC Security Middleware (`server/middleware/`)

    - `rbacMiddleware.js`: Role checking (`admin`, `warden`, `student`).
